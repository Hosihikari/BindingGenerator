# Hosihikari.Bindings.Generator

[English](README.md) | [简体中文](README.zh_hans.md)

The generator turns the versioned IR into the C ABI **BindingShim** and the native-style C# **Interop**. It does not produce the hand-written .NET Idiomatic layer.

## Boundary

- **Input**: IR shards produced by the libTooling frontend, plus the IR library contract.
- **Output**: generated C++ (BindingShim) and C# (Interop) sources. Both are committed in the binding repositories and verified by a CI diff.
- **Not here**: the hand-written Idiomatic wrappers, the HostingShim, or any CLR hosting.
- The IR library is a sibling checkout (`../Ir`); in CI it is pulled with `actions/checkout` using a pinned `repository`/`path`.

## Commands

```shell
dotnet run --project src/Hosihikari.Bindings.Generator/Hosihikari.Bindings.Generator.csproj -c Release -- version
dotnet run --project src/Hosihikari.Bindings.Generator/Hosihikari.Bindings.Generator.csproj -c Release -- validate-ir tests/fixtures/basic/ir-manifest.json tests/fixtures/basic
dotnet run --project src/Hosihikari.Bindings.Generator/Hosihikari.Bindings.Generator.csproj -c Release -- emit tests/fixtures/basic/ir-manifest.json tests/fixtures/basic artifacts/emitted --abi-header ../Bindings.Abi/native/hosihikari_abi.h
```

`validate-ir` reads the manifest and every `*.jsonl` under the shard directory, then runs the IR validator. `validate-coverage` does the same for `coverage/summary.json` + `coverage/manifest.jsonl`.

`emit` writes `interop/` (C#), `shim/` (C++ BindingShim), and `coverage/` (manifest + summary). Pass `--native-root <path>` to emit the real BindingShim for the IR's source files:

```shell
dotnet run --project src/Hosihikari.Bindings.Generator/Hosihikari.Bindings.Generator.csproj -c Release -- emit \
  artifacts/llapi-full-ir/ir-manifest.json artifacts/llapi-full-ir artifacts/llapi-real-shim \
  --native-root C:/path/to/LeviLamina --abi-header ../Bindings.Abi/native/hosihikari_abi.h
```

`--abi-header` points at `Hosihikari/Bindings.Abi`'s `native/hosihikari_abi.h`; the emitter copies it into every shim directory so the shim build stays self-contained. Generated C# references `Hosihikari.Bindings.Abi` for `StringView`, `ArrayView`, `SharedHandle`, and the version-checking `ShimLibrary` loader.

Without `--native-root`, `emit` writes the contract stubs used by the fixture CI, unless `--symbol-dispatch` is set.

### Symbol dispatch

`--symbol-dispatch` emits the same C# Interop and binding table from symbol-level IR without game headers:

```shell
dotnet run --project src/Hosihikari.Bindings.Generator/Hosihikari.Bindings.Generator.csproj -c Release -- emit \
  artifacts/symbol-ir-1.21.3/merged-levi-final/ir-manifest.json artifacts/symbol-ir-1.21.3/merged-levi-final \
  artifacts/symbol-dispatch --abi-header ../Bindings.Abi/native/hosihikari_abi.h \
  --symbol-dispatch --target-module bedrock_server
```

Direct members resolve `module base + rva` on Windows or `module base + address` on Linux; if no address is recorded, the shim falls back to `GetProcAddress`/`dlsym` with the symbol name. Virtual members use the per-configuration `vtableIndex`, scoped to the member's declaring class; a class whose symbol stream has no vtable falls back to direct symbol/RVA dispatch. The index is relative to the vtable address point on both platforms. Instance methods that return a non-trivial `std::string` follow the MSVC member ABI (`this` in RCX, hidden result buffer in RDX); static methods follow the free-function convention. Non-trivial results are destroyed through the target module's own `std::basic_string` destructor, recorded in the IR manifest as `supportSymbols.stdStringDestructor`, so strings allocated by a game-private allocator are not released by the shim's allocator; fixtures without that support symbol fall back to local destruction. `Core::PathBuffer<std::string>` projects as `string` because the wrapper's layout and non-trivial return ABI match its single `std::string` member. `--target-module` names the hosting module. The mode accepts scalars, enums, `std::string`/`std::string_view`, single-level pointers/references, and records passed or returned by value. Records keep their generated wrapper type in C#; the shim handles the ABI: small `triviallyCopyable` records travel in a register, larger records are copied to a stack temporary and passed by pointer (or returned through the hidden buffer), and non-trivial records use their copy constructor and destructor symbols. A record that is only trivially destructible — `AABB`, `Vec2`, `Brightness` — is copied as bytes but always uses the hidden-reference convention, even when small, because a user-provided copy constructor makes it non-trivial for calls. Top-level `const` on a by-value record return (for example `Tick const`) resolves through the same record table; pointer and reference returns keep the borrowed path. Public byte-aligned fields, including fields inherited through non-virtual bases, are exposed as offset-based properties. `std::vector<T>` parameters and by-value results are supported when the element is a scalar or enum, `std::string`/`std::string_view`, a single-level pointer (surfacing as `nint[]`), or a record with a recorded layout and trivial destructor (IR 1.5.1 `declaration.triviallyDestructible`); element records travel through an aligned byte blob, so a user-provided copy constructor such as `AABB`'s is accepted, returned record elements become owned copies backed by a generated destroy entry, and reference or pointer vector results remain borrowed handles. `std::optional<T>` parameters and results support scalars, strings, and trivially copyable records (records use a layout-compatible blob and become owned wrappers on return). `std::shared_ptr<T>` parameters and results keep one shared reference alive in a shim holder; `std::weak_ptr<T>` results are locked once into a strong snapshot, and expired references produce a null handle. `OwnerPtr<T>` and `StackRefResult<T>` use the same shared ABI, `WeakRef<T>` uses the weak ABI, and `Bedrock::NonOwnerPointer<T>` keeps the returned control block alive while exposing the object stored in its first field; `gsl::not_null<...>` is unwrapped around these wrappers. Managed binding-table `bool` results — including variant alternatives — are declared as `byte` and normalized with `!= 0`, because Windows x64 only guarantees the low byte of the return register. `optional_ref<T>` parameters and results use the optional presence flag with borrowed references. The header supplement contributes enums, dependency record declarations (including sequence element types), layouts, and the `triviallyCopyable`/`triviallyDestructible` facts. Maps, callbacks, variants, and custom owning wrappers remain stubs; a map requires named key/value types and matching hash/equality functors, which the symbol stream does not carry. Constructors require a recorded layout so the shim can allocate; a class without a layout can still expose borrowed handles from static factories.

`tests/symbol-dispatch/run.ps1` builds a synthetic PE/PDB fixture, runs the symbol frontend, emits the dispatch shim, and runs the C# smoke test. `tests/fixtures/symbol-dispatch` plus `tests/symbol-dispatch/linux-fixture.cpp` cover the Linux resolver and vtable offset in the `cli` CI job. `tests/bds-smoke` runs the same shim inside a real 1.21.3 server: a LeviLamina `preload-native` mod hosts the CLR through `nethost`/`hostfxr`, calls the managed `BlockPos`/`ChunkPos`/`Vec3` projection through RVAs, invokes scalar, container, and `Core::PathBuffer<std::string>` getters on the live `AppPlatform` service object, and checks the returned storage, userdata, and current-storage paths.

### Real BindingShim v1

- The C ABI is one versioned `HosihikariBindingTableV1` per carrier surface. Handles are `void*`; owned handles come from constructor factories and are released by the generated disposer. Table fields are named from the stable function identity (for example `hs_method_1a2b3c4d`), not from the slot ordinal; the ordinal remains only the physical array position, so adding a function does not rename existing call sites. Field strings are returned as borrowed `HosihikariStringView` values that the managed side copies immediately; string parameters are `(const char*, size_t)` UTF-8 pairs.
- Constructors, destructors, public fields, and supported methods are projected. Members that the generator deliberately refuses are emitted as `NotSupportedException` stubs marked with `[Obsolete]` carrying the same reason; calling one produces compiler warning CS0618 and an IDE strikethrough, and projects can escalate it with `<WarningsAsErrors>CS0618</WarningsAsErrors>`. Constructors and methods accept multiple parameters. Constructors may take mutable and rvalue references to public declarations that have generated wrappers; the shim passes those parameters by dereferenced address. A method may return `void`, a fundamental, an enum, an opaque pointer, a string, or an eligible by-value record; a single-level `T*`/`T&` return to a public declaration surfaces as a typed borrowed wrapper (`T?`/`T`) whose `Dispose` only invalidates the wrapper and whose `ReleaseHandle` refuses borrowed handles, leaving ownership with the native side, and `optional_ref<T>` returns use the same wrapper path with the hidden presence flag; the public `(nint handle)` constructor remains the owning path for raw handles; single-level pointer parameters to public declarations are nullable (`T?`) and map null to a null pointer, while rvalue-reference parameters stay non-null wrappers and deeper indirection stays `nint`; accessible public bases, including transitive bases, receive `As<TBase>()` upcasts and polymorphic bases receive `TryAs<TDerived>()` RTTI downcasts for every transitive derived class, both returning borrowed wrappers; string results are copied into a thread-local shim buffer and the managed wrapper copies them immediately. Multiple string parameters are pinned independently per call; UTF-8 encodings of at most 256 bytes use a stack buffer instead of a per-call byte array. Enums use their underlying integer ABI. By-value record arguments are dereferenced from caller handles; by-value record results are copied into shim-owned objects that the managed wrapper can dispose. Record and container fields are exposed through borrowed address views; array fields are getter-only. `std::vector<T>` results use a borrowed `HosihikariArrayView` and surface as `T[]`/`string[]`/`nint[]`, including pointer elements, with empty results returning `Array.Empty<T>()`; vector parameters expand to a hidden `(element pointer, count)` pair and surface as `T[]`/`string[]`/`Variant[]`, including record and variant elements, with multiple vector parameters per call; each vector gets its own pinned element view; `std::initializer_list<T>` parameters stay unsupported because C++ cannot construct a runtime-length initializer list, but the affected classes expose equivalent vector overloads; `std::vector<std::pair<string, uint64>>` parameters surface as `KeyValuePair<string, ulong>[]`, with string keys and values sharing one UTF-8 arena per call; `std::optional<T>` parameters and results use a hidden presence flag; managed values are nullable scalars, `string?`, or owned `T?`; `std::unique_ptr<T>` results release ownership as an owned `T` handle; `unique_ptr` parameters transfer ownership from the wrapper, which releases its handle before the call and throws if reused; abstract interfaces with a public virtual destructor receive a disposer when returned this way. `std::shared_ptr<T>` results return a `SharedHandle` that keeps one shared reference alive and releases it on dispose; `shared_ptr`/`weak_ptr` parameters accept a `SharedHandle`, and the shim recovers the typed reference through a type-checked holder. `optional_ref<T>` parameters and results use the optional presence flag with borrowed references; managed values are `T?`/`nint?`. `nonstd::expected_lite::expected<T, E>` results return `T` and surface failures as `InvalidOperationException` carrying the native error message; `E` may be `ll::Error` or a string. `std::variant<T...>` values with string, scalar/enum, pointer, and copyable-record alternatives receive a generated owned wrapper with per-alternative `Create`/`As`/`Is`, `Index`, and `Dispose`; by-value parameters copy, `const&` parameters borrow, and by-value results copy into an owned handle. A public copyable class whose members are inherited (no recorded fields, constructors, or destructor) is accepted as a record alternative; the generator emits the destroy function needed by its `Dispose`. `endstone::NotNull<T>`/`Nullable<T>` returns use `SharedHandle`; sequence returns distinguish borrowed pointer elements (`nint[]`), owned elements (`T[]`/`T?[]` for records and `unique_ptr`), and shared elements (`SharedHandle[]` for `shared_ptr`/`NotNull`/`Nullable`); `unordered_set<T*>` returns borrowed address arrays. `std::chrono::time_point<std::chrono::system_clock>` maps to Unix milliseconds; other clocks map to their native tick count; `std::chrono::duration` maps to its native count; `optional` time values use `long?`. Returned `std::function<R(Args...)>` values become generated callable wrappers with `Invoke` and `Dispose`. Reference returns of variant, callable, chrono, `typeid_t`, `strong_ordering`, and filesystem-path values are copied through the same projection instead of surfacing as opaque handles; pointers to those types remain borrowed handles. `Bedrock::typeid_t<C>` maps to `ushort`, `std::strong_ordering` to `sbyte` (-1/0/1), and `std::filesystem::path` to a UTF-8 string; optional forms follow the scalar/string rules. `std::unordered_map<K, V>` parameters and results use a managed `Dictionary<K, V>`; keys support string/scalar/pointer and values support string/scalar/pointer, record copies, and variant copies. Map parameters reuse the vector arena strategy: string keys and values share one UTF-8 arena per call, and maps of at most 16 entries use a stackalloc `MapEntry` buffer. Reference and pointer results keep a borrowed handle when the entry types cannot be projected.
- The default link-safe mode projects public non-template classes that are complete in the IR source root and have only inline methods and link-safe bases. `--link-carrier` also admits public concrete template instances and links the carrier import library, fmt, and prelinked Bedrock imports. Template arguments must be accessible; incomplete arguments are admitted only for standard or supported third-party types. Member templates, rvalue-qualified members, and variable templates are not projected, and a template destructor must have a visible definition before a disposer is emitted. Assignment operators are projected for non-template classes; assignments on template specializations are skipped because the underlying operation may require complete template arguments or may be deleted. Static methods and static fields are projected without `self`. Abstract classes do not receive factories. Classes that store `string_view` or `std::string` reference fields receive holder-backed factories: the shim copies each string argument into a holder and constructs the object against those copies, so the views and references stay valid until the wrapper is disposed. An abstract class with exactly one pure virtual callback (pointer/reference/scalar parameters, `void`/scalar/enum return), a public virtual destructor, and an accessible scalar/enum/shared or implicit default constructor receives a director factory: the shim subclasses the interface, forwards the virtual call to `(invoke, userData, release)`, and returns a `shared_ptr` handle. Every generated wrapper also exposes `Borrow(nint)` for a non-owning view of a raw handle. Public namespace-level inline functions with scalar/enum/string/pointer parameters and `void`/scalar/enum/string/pointer results are projected into one `Functions` static class per native namespace; this pass runs only in `--link-carrier`/`--virtual-dispatch` mode because an inline body may still reference out-of-line symbols.
- Every table function is a C++ function-try-block. Native exceptions are captured into a thread-local message exposed by `hosihikari_get_last_error`; no C++ exception crosses into managed code. Factory failures return a null handle and the generated `Create` methods throw `InvalidOperationException` with that message.
- `std::function<R(Args...)>`, `brstd::move_only_function<R(Args...)>`, and `brstd::function_ref<R(Args...)>` parameters are exposed as `(invoke, userData, release)` triples. The shim wraps a shared callback state in the requested callable type (`std::function`, `brstd::move_only_function`, or `brstd::function_ref`); the last copy invokes `release(userData)`. v1 supports scalar and enum results with scalar, enum, string, pointer, reference, and by-value record arguments; const scalar, enum, and string references cross as values.
- `--ll-allocator` routes the shim's global `operator new`/`delete` through `ll::memory::getDefaultAllocator()`. Use it with carriers such as LeviLamina that replace the global allocator; mock carrier fixtures omit it.
- `NativeMethods.Load(path)` validates the exported table version and `sizeof(Table)` before use. The table's `version` and `size` are the first two fields.

`frontend/build-shim.ps1` compiles the generated shim with clang-cl and `/MD` against the LeviLamina include environment. Pass `-AdditionalLinkLibrary` for carrier/package libs and `-DelayLoadLibrary LeviLamina.dll` for a standalone smoke build. `frontend/build-carrier-shim.ps1` compiles the object, runs `prelink` to generate the Bedrock runtime import library, and links the carrier shim. `frontend/smoke-shim.ps1` emits, builds, and runs the end-to-end smoke test in `tests/BindingShimSmoke`; add `-LinkCarrier` to use the carrier build with delay-loading.

## Local LLAPI slice

`frontend/run-local.ps1` parses `ll/api/event/Event.h`, writes IR under `artifacts/llapi-ir`, and validates it. `frontend/run-umbrella.ps1 -Module ll/api` parses the full `src/ll/api` plus `src-server/ll/api` umbrella, reuses the LeviLamina `compile_commands.json`, and currently yields 1,530 declarations / 6,145 members at IR 1.3.0. Public record types referenced by value from filtered signatures are added with their constructors, destructor, and fields even when their headers sit outside the module filter. The IR records each function's and method's `inline`/`defined`/`consteval` facts, member templates, ref qualifiers, enum underlying types, and class traits (`abstract`, `copyConstructible`), which the BindingShim planner uses for eligibility and ownership.

```shell
powershell -File frontend/run-umbrella.ps1 -Module ll/api -Output artifacts/llapi-full-ir
powershell -File frontend/smoke-shim.ps1 -IrDirectory artifacts/llapi-full-ir
powershell -File frontend/smoke-shim.ps1 -IrDirectory artifacts/llapi-full-ir -LinkCarrier
```

The complete LLAPI umbrella currently selects 496 link-safe functions, or 3,819 functions when built with `--link-carrier` against `LeviLamina.lib`. The slice covers `ll::event::EventId`, `ll::event::EventIdView`, `ll::hash_utils::HashedIdBase`, `ll::hash_utils::HashCombiner`, `ll::data::Version`, and the other eligible classes. The smoke test creates a native `EventId` from a managed string, reads its name and hash, compares two `HashedIdBase` views, calls `HashCombiner::hash()`, and round-trips `ll::data::Version` through string construction, `to_string()`, field getters, `valid(string)`, and `isIdenticalTo(Version)`. The remaining members keep their Interop stubs and are recorded in the coverage manifest with the `interop` emitter only.

## Endstone surface

`frontend/run-endstone.ps1` parses the Endstone public umbrella (`include/endstone/endstone.hpp`) with expected-lite and nlohmann_json headers. `--virtual-dispatch` emits a link-free shim for the header-only virtual interfaces: inline members and virtual methods are called through the host-provided vtables, while non-virtual out-of-line members remain stubs. `frontend/build-endstone-shim.ps1` compiles the generated table against the Endstone headers. The Endstone 0.11.14 surface currently selects 2,364 functions, including eligible template instances, inline/constexpr static fields, assignment operators on non-template classes, and inheritance casts.

`frontend/run-endstone.sh` generates the `linux-x64-server` configuration on Linux. The `endstone-linux-ir` CI job builds the frontend against LLVM 23.1.3, generates and validates the IR, emits the Interop and shim, compares the emitted Interop byte-for-byte with the committed Windows-IR output, and compiles the shim. Fixed-width spellings, standard-library iterator types, and `system_clock::time_point` durations are normalized to the Windows form so declaration ids, table field hashes, and coverage stay identical across platforms (ADR 0018).
